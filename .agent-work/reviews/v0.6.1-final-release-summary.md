# Linux Diagnostic Engine v0.6.1 Release Summary

## Overview
This is a hotfix release addressing a critical runtime crash on fresh machines with restrictive `/boot` permissions (0700 root:root). The issue was confirmed through real Z13 evidence and has been fixed with surgical changes to improve robustness.

## Changes Made

### Core Implementation
- Enhanced kernel inventory functions (`_get_bootable_kernels_from_boot` and `_get_bootable_kernels_from_modules`) to handle permission errors gracefully
- Modified reporting logic to distinguish between "unknown source" (None) vs "empty source" ([])
- Added comprehensive error handling for filesystem access issues
- Implemented proper restriction tracking for inaccessible directories

### Version Bump
- Updated version from 0.6.0 to 0.6.1 in:
  - `pyproject.toml`
  - `syscheck.py`

### Test Coverage
- Added extensive regression tests for:
  - Permission errors on `/boot` (mode 0700)
  - Missing directories
  - Race conditions during directory enumeration
  - Proper handling of various error scenarios
  - Full system integration tests with mocked inaccessible paths

## Technical Details

The fix addresses a specific crash condition where:
1. `/boot` directory had restrictive permissions (0700 root:root)
2. The `ls /boot` command would fail with PermissionError
3. This would cause `syscheck` to crash instead of gracefully handling the situation

Now, when `/boot` is inaccessible, the system:
- Reports "(niedostępne — brak uprawnień lub katalogu)" for kernel boot images
- Records appropriate restrictions in the findings list
- Continues execution without crashing
- Maintains backward compatibility

## Validation
- All existing tests pass
- New tests cover the exact crash scenario
- Real Z13 evidence confirms fix effectiveness
- No breaking changes introduced

## Release Process
This release is ready for deployment and follows the established release procedure.
