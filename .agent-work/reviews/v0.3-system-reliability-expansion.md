## 8. Source authority and implementation

Two concrete defects were closed:

1. btrfs device stats no longer turns empty or unrecognizable successful output
   into an authoritative all-zero report. Parseable positive counters remain
   visible; malformed mixed output marks the Observation incomplete and lowers
   confidence to Guessing.
2. System failed-unit queries, selected current-boot reliability queries, Btrfs
   stats/scrub failures, Btrfs show command absence, and optional NVMe tool
   failures no longer disappear silently. Explicit status tokens are retained:
   FAILED_EXECUTION, TIMEOUT, COMMAND_NOT_FOUND, PERMISSION_DENIED,
   MALFORMED_OUTPUT, and TRUNCATED_OUTPUT.

## 10. False-positive controls

Covered controls include:

- Btrfs No missing devices and malformed/empty stats do not become failures or authoritative zeroes.
- Limited/truncated Btrfs MISSING stays raw but is rejected.
- NVMe initialization/configuration/completed-I/O and unrelated SMART text do not match controller events.
- Kernel OOM requires exact markers; oomd-like pressure text alone does not match.
- Service query failure and empty/malformed output never become a failed service.
- WirePlumber-only and mixed-owner segfaults have one deterministic owner.
- Successful filesystem I/O text does not match; read-only remount and exact block-I/O do.
- Truncation preserves partial evidence and prevents negative claims.
