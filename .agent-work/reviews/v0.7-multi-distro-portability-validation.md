## Pre-edit contract diff

### CURRENT_GENERIC

There was no generic package-manager profile. New or unrecognized IDs selected
Arch commands. The engine initialized to Arch before distro detection.

### CURRENT_ARCH_SPECIFIC

Arch package checks used pacman. The kernel query was a Bash pipeline with
PIPESTATUS and grep; kernel module counting inspected only /usr/lib/modules,
and the boot image counter recognized only vmlinuz-* under /boot.

### FEDORA_GAP

The Fedora/RHEL profile queried RPM kernel packages, but dnf repoquery and
dnf list installed were also used for orphan and foreign/AUR classifications.
Those classifications are not equivalent across package families and can
depend on optional DNF tooling or repository state.

### DEBIAN_UBUNTU_GAP

Kernel packages were parsed from human-oriented dpkg -l output. apt list
obsolete/origin views did not establish autoremove or foreign-package
semantics. Debian and Ubuntu module, boot, and EFI paths were not separated.

### TOOLING_ASSUMPTION

Journal filtering uses Bash and GNU grep -P. Human-readable systemd and other
tool output remains environment- and locale-sensitive. The Arch package query
also had a Bash-only pipeline.

### AUTHORITY_RISK

Missing distro metadata fell through to Arch. A package query failure could
prevent independent module and boot inventory. A hidden or protected boot path
must remain unknown, and a package count mismatch must not establish an orphan
or broken kernel.

### IMPLEMENTATION_REQUIRED

Parse os-release without executing it; route unknown or malformed metadata to
a generic profile; use native machine-readable package sources; keep unsupported
package classifications unclassified; inventory both module roots and visible
boot/EFI sources independently; retain provenance and unknown states.

### TEST_ONLY

Cross-vendor GPU cases, distro ID variants, package layouts, alternate kernel
image names, UKI paths, missing tools, permission failures, and privacy samples
were suitable for synthetic regression cases.

### DEFERRED

Real Fedora and Debian/Ubuntu host or VM checks; readable mounted boot/ESP
evidence; full non-systemd support; non-GNU grep portability; locale-matrix
testing of human-readable command output; and any new kernel-orphan detector.

## Support and authority matrix

userspace image only; SYNTHETIC means deterministic fixture or test input;
NOT VALIDATED does not mean absent. For commands, run_cmd retains exit status,
stdout, stderr, timeout, permission denial, and not-found separately. A
nonzero result with useful text remains visible but does not become an

The Fedora kernel RPM ecosystem has split packages including kernel,
kernel-core, kernel-modules, kernel-modules-core, and kernel-modules-extra;
the parser deduplicates kernel versions and does not treat each module package
as a separate kernel ([Fedora kernel package index](https://packages.fedoraproject.org/pkgs/kernel/)).

## Implementation and regression corpus

- Distro parsing uses shlex tokenization without shell evaluation. Exact
  CachyOS/Arch, Arch, Fedora, Debian, Ubuntu-with-Debian-like, unknown-ID,
  missing, malformed, and command-unavailable cases are covered.
- Debian kernel and installed-package inventory use dpkg-query machine fields;
  no online apt state is needed. RPM query formats are explicit. Orphan and
  foreign/AUR classifications are left unconfigured on Fedora and Debian
  rather than mislabeling obsolete or all-installed packages.
- Module versions are collected independently of package-query success from
  /usr/lib/modules and /lib/modules, with merged-/usr alias deduplication.
- Boot image names include vmlinuz, vmlinux, Image, bzImage, and their common
  prefixed forms. initramfs/initrd files, direct EFI files, EFI/Linux UKIs,
  and EFI/BOOT files are counted separately. The old /boot count now consumes
  the same visible inventory; unavailable or partially inspected paths return
  unknown. A readable empty directory means only zero visible recognized
  artifacts at that path.
- GPU tests cover AMD 1002, Intel 8086, NVIDIA 10de, AMD+NVIDIA, Intel+NVIDIA,
  multiple same-vendor devices, exact BDF correlation, missing lspci,
  contradictory identity, malformed input, and non-display PCI. Vendor/device
  IDs have field-level provenance. No commercial model inference is performed.
- Missing lspci, btrfs, nvme, sensors, upower, resolvectl, systemd-analyze,
  Bash, and grep are exercised as not-found or command failure states. The
  source record becomes limited/failed; no finding is resolved from absence.
- Existing Btrfs, journal/systemd, lifecycle, false-resolution, and
  real-world hardening suites remain in the full regression run. No detector
  was added for kernel count mismatch, extra module trees, alternate boot
  layout, missing optional tools, incomplete Btrfs output, or AMDGPU SVM.

Shell audit: the Arch package inventory no longer uses Bash PIPESTATUS or a
shell pipeline. The existing journal filters still build Bash pipelines with
GNU grep -P (two builders, four PIPESTATUS references; five Bash invocations
remain in syscheck.py). The synthetic grep -P probe succeeded on the CachyOS
host and both target containers. If Bash is missing, the source is not found;
if grep is missing, the pipeline exits nonzero and remains failed. This is safe
degradation for the three target families, not portability proof for BusyBox
or BSD grep.

No LC_ALL=C override is applied. Distro/package parsing uses structured IDs and
machine query formats; GPU display class parsing uses numeric PCI class codes.
Remaining human-readable journal/systemd/network output may become malformed
under another locale and is kept unknown rather than treated as zero or
healthy. Full locale variation testing is deferred.
