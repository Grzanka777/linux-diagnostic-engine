## 2. Failure Reproduction

### Observed Defect
On a fresh machine where `/boot` is permission-restricted (mode `0700` owned by `root:root`), running `lde run` as an unprivileged user crashed with an uncaught `PermissionError`:

```text
Traceback (most recent call last):
  File "/path/to/syscheck.py", line 5941, in run_all
    self.collect_base_info()
  File "/path/to/syscheck.py", line 3441, in collect_base_info
    bootable_kernels = _get_bootable_kernels_from_boot()
  File "/path/to/syscheck.py", line 1491, in _get_bootable_kernels_from_boot
    for f in boot_dir.iterdir():
PermissionError: [Errno 13] Permission denied: '/boot'
```

### Technical Reproduction
Reproduction was confirmed using `Path.iterdir` raising `PermissionError(13, "Permission denied", "/boot")`:
1. Directly calling `_get_bootable_kernels_from_boot()` reproduced the unhandled exception at line 1491.
2. Executing `SysCheckEngine().run_all()` failed in `collect_base_info()`, aborting diagnostic execution before reporting.

---

## 3. Root Technical Cause

In `syscheck.py`, `_get_bootable_kernels_from_boot()` checked `if not boot_dir.is_dir(): return []`, and then unconditionally iterated `boot_dir.iterdir()`.
1. On POSIX systems where `/boot` inode metadata is accessible from `/` but `read` permission on `/boot` is restricted to root (`drwx------`), `boot_dir.is_dir()` succeeds via `stat()`.
2. Calling `boot_dir.iterdir()` attempts `opendir("/boot")`, which raises `PermissionError: [Errno 13] Permission denied: '/boot'`.
3. The function lacked any exception handling for environmental permission denial or filesystem races.
4. Furthermore, returning `[]` on failure would be flawed: downstream consumers would interpret `[]` as an authoritative assertion that zero kernel images exist in `/boot`.

---

## 4. Source-Authority Analysis

| Question | Analysis |
|---|---|
| **1. What source is accessed?** | The host filesystem at `/boot` (`_get_bootable_kernels_from_boot`) and `/usr/lib/modules` (`_get_bootable_kernels_from_modules`). |
| **2. When is it authoritative?** | Only when the directory is accessible and readable. An empty result `[]` is authoritative only when the directory was successfully scanned and contained zero matching kernel images or modules. |
| **3. What does permission denial mean?** | Permission denial (`PermissionError`, errno 13) means the engine lacks privileges to inspect the directory. The true count of images in `/boot` is unknown and unavailable; it does NOT mean zero images exist. |
| **4. How is unavailable/limited represented?** | At the function boundary: `None` (strictly distinct from `[]`). In `self.restrictions`: an explicit restriction entry. In the markdown report: `(niedostępne — brak uprawnień lub katalogu)`. |
| **5. Can downstream code confuse absence of evidence with evidence of absence?** | No. Downstream code checks `bootable_kernels is not None`. An unreadable `/boot` yields `None`, avoiding false zero-kernel assertions (`Obrazy w /boot: 0`). |
| **6. Can verification falsely mark a Finding resolved?** | No. `/boot` does not participate in positive resolution. If a future Finding relies on `/boot`, the restriction in `self.restrictions` matches `_NON_AUTHORITATIVE_MARKERS` and forces `UNVERIFIED`. |
| **7. Can a report incorrectly claim health?** | No. The engine clearly reports that `/boot` images could not be inspected due to lack of privileges, preserving honest diagnostic boundaries without claiming missing kernels. |

## 5. Production Changes

### 1. `syscheck.py`: `_get_bootable_kernels_from_boot()` & `_get_bootable_kernels_from_modules()`
- Added optional path parameter (`boot_dir: Path | str = Path("/boot")` and `modules_dir: Path | str = Path("/usr/lib/modules")`) to support dependency injection in tests while preserving zero-argument compatibility.
- Added explicit return type `Optional[List[str]]`.
- Wrapped directory inspection in `try ... except (PermissionError, FileNotFoundError, NotADirectoryError, OSError): return None`.
- Wrapped inner loop iteration in `try ... except OSError: continue` to survive enumeration races (entries deleted while traversing).
- Returns `List[str]` (including `[]`) only when the directory was readably and authoritatively scanned.

### 2. `syscheck.py`: `collect_base_info()`
- Checked `bootable_kernels is not None` and `bootable_versions is not None`.
- When `None`, formats summary lines as `(niedostępne — brak uprawnień lub katalogu)` instead of attempting `len()`.
- Records an explicit, deduplicated restriction in `self.restrictions` documenting that `/boot` or `/usr/lib/modules` could not be read without root privileges.

### 3. `syscheck.py`: `collect_packages()`
- Checked `boot_images is not None` and `modules_versions is not None`.
- Formats report lines with honest unavailable status when `None`.
- Ensures restrictions are recorded if not already appended during earlier phases.

## 7. Kernel Inventory Semantics

LDE correlates three kernel sources:
1. **Installed packages:** queried via package manager (`pacman`, `dpkg`, `rpm`). Authoritative for installed package counts.
2. **Modules tree:** `/usr/lib/modules/`. Reflects driver trees installed on disk.
3. **Boot images:** `/boot/vmlinuz-*`. Reflects bootable images present in `/boot`.

When `/boot` is unreadable:
- `_get_bootable_kernels_from_boot()` returns `None`.
- The engine does NOT assert zero images (`len` is never evaluated on `None`).
- No mismatch Finding is generated because package count rules evaluate package manager query results (`kernels_result`), not `/boot`.
- The limitation is recorded in `engine.restrictions`.
- When `/boot` is readable, existing behaviour is 100% preserved.

## 9. False-Resolution Verification

Proved that:
1. When a baseline finding is derived from an independent source (e.g. `KRNL-INFO-001` querying `kernel_package`), a permission restriction on `/boot` does not prevent the finding from properly resolving if the package query was authoritative.
2. When a baseline finding is tied to `/boot` (source query `/boot`), the restriction `Katalog /boot jest niedostępny bez uprawnień roota...` matches non-authoritative markers and causes `FindingLifecycleComparator` to return `UNVERIFIED`, preventing false resolution.
