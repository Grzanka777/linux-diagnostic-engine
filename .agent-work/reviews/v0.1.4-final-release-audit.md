## 4. ACPI precision

`_journal_filter_command()` and `_journal_count_command()` now shell-quote the
existing patterns and use PCRE-compatible grep, matching the existing Python
regex contract (`(?:...)`, `\b`, and `\s`). This fixes the demonstrated real
shell mismatch and the apostrophe quoting failure without broadening the
ACPI rule.

The exact `ACPI BIOS Error ... AE_NOT_FOUND` replay reaches one existing
`PLATFORM-ACPI-FIRMWARE-ERROR-001` Raw -> Observation -> Evidence -> Finding
chain. Duplicate and benign informational controls remain rejected, and the
existing P2 severity/recommendation semantics are unchanged.

```text
ACPI_PRECISION_AUDIT = PASS
```

## 5. Kernel taint precision

The existing `Tainted:` marker remains supported. The added expression is
limited to the explicit kernel forms `tainting kernel` and `taints kernel`;
there is no catch-all `taint` substring match. The collector excludes explicit
negations such as `Not tainted`, `untainted`, and `not tainting kernel`.

The replay covers force-probe context, signature failure, and an out-of-tree
`razermouse` module. Only the two actual taint marker lines become matched
payload lines; one replay yields one existing `KERNEL-TAINT-001` Finding with
the existing evidence ID. Existing duplicate and negative controls pass.

```text
KERNEL_TAINT_PRECISION_AUDIT = PASS
```

## 6. Btrfs false-positive protection

Privilege-limited `MISSING` output remains visible in the report and raw
diagnostic payload. The adjacent report text marks it incomplete and
non-authoritative. The existing Btrfs rule rejects only the combination of
`device_missing` and `privilege_limited=True`; the authoritative/unflagged
`device_missing` Finding behavior remains covered.

The restriction is preserved, no sudo/root behavior was added, and the exact
installed artifact produced no Btrfs Finding for the live privilege-limited
`MISSING` output.

```text
BTRFS_FALSE_POSITIVE_PROTECTION = PASS
```

## 7. Pipeline accounting architecture

`pipeline_accounting` is an internal derived projection created after the
existing interpretation engine finishes. Each Observation maps to either its
Finding or a stable rejection reason. It is not serialized, does not appear in
the public report, does not add AI/probabilistic logic, and does not replace
the existing Raw -> Observation -> Evidence -> Finding state flow.

Focused tests exercise both Finding and deterministic rejection paths,
including `privilege_limited_btrfs_missing`.

```text
PIPELINE_ACCOUNTING_ARCHITECTURE = PASS
```
