## 4. Architecture/ownership

Finding-family ownership is explicit in `diagnostic_rules.py`: the default
registry exposes 33 unique `finding_id_patterns`, and source-only rules can
declare an empty Finding-family tuple. The explanation registry in `syscheck.py`
is validated against that runtime detector inventory, including declaration
presence, key identity, and mutation-like command rejection.

The lifecycle comparator owns snapshot validation, source authority, and
`NEW`/`PERSISTENT`/`RESOLVED`/`UNVERIFIED` classification. The explain layer
uses persisted Finding IDs and Evidence IDs and calls the comparator's
source-limitation boundary. The CLI uses the same public functions for direct
script and installed entrypoint execution. The direct-script module-identity
case is covered by regression tests.

There is a small maintainability opportunity to extract shared source-key
logic between lifecycle and explain limitation paths later. It is not a
release-safety defect: the current ownership is explicit, registry drift is
checked, snapshot validation is centralized, and the focused adversarial tests
cover the boundary. Classification: `COHESIVE_ENOUGH_FOR_V0_6`.

address, and UUID were all absent from sanitized outputs. The sanitized JSON
