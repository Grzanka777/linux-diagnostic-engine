## Implementation and evidence routing

- ACPI journal filtering now uses shell-safe quoting and PCRE-compatible
  matching for the existing Python-style contract. The real
  `ACPI BIOS Error ... AE_NOT_FOUND` replay reaches the existing
  `PLATFORM-ACPI-FIRMWARE-ERROR-001` Finding once, with Raw -> Observation ->
  Evidence -> Finding lineage. The negative `ACPI: Interpreter enabled`
  control is rejected before the raw stage.
- Kernel taint matching retains the existing `Tainted:` precision and adds
  only the existing real marker forms `tainting kernel` and `taints kernel`.
  The replay covers force-probe context, signature failure, and an
  out-of-tree `razermouse` module; negated/untainted controls remain
  rejected. One replay produces one existing taint Finding.
- Internal `pipeline_accounting` records each Observation as either a Finding
  or a deterministic rejection. It is intentionally not serialized, so
  snapshot schema 3 is unchanged.
- Privilege-limited Btrfs `MISSING` remains raw evidence and is rendered as
  incomplete/non-authoritative. The existing Btrfs rule rejects that specific
  privilege-limited state without creating a Finding. Existing unflagged
  `device_missing` behavior remains covered and unchanged.
- Product metadata is `0.1.4`; report compatibility remains `2.1.0`; snapshot
  schema remains `3`; runtime dependencies and the CLI surface remain
  unchanged.
