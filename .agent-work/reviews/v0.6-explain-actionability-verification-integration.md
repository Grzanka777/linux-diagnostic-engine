## 2. Architecture assessment

Verdict: PASS.

The implementation keeps one canonical explainability registry in
`syscheck.py` (`FindingExplanationDefinition` and
`FINDING_EXPLANATION_REGISTRY`). It is not derived from Markdown report text.
`diagnostic_rules.py` declares the public Finding ID patterns emitted by each
default rule; registry validation compares those patterns and fails closed on
missing or orphaned definitions.

Snapshot enrichment reads the persisted `FindingSnapshot` and follows its
`evidence_ids` and `source_observation_ids` to persisted Evidence and source
lineage. It does not collect diagnostics for static explain and does not infer
root cause, probability, intent, or repair success.

The source-limitation helper is shared with the lifecycle authority boundary.
The direct script entrypoint also now resolves `__main__` correctly, avoiding
duplicate module identities that previously serialized enum names instead of
canonical values in direct-entrypoint snapshots.

## 3. Explain metadata contract

`lde explain <FINDING-ID>` returns compact English fields:

- Finding, title, summary, severity, confidence;
- why LDE reports it and possible impact;
- actionability, investigation, verification, sources, and limitations;
- runtime status, source status, source Observation IDs, Evidence IDs, and
  linked persisted Evidence when `--snapshot` is supplied.

Static severity and confidence use the explicit `RULE_DERIVED` marker because
no runtime evidence is available. Snapshot mode uses the persisted runtime
severity and confidence. Dynamic storage IDs resolve through the deterministic
`STORAGE-USAGE-*` family pattern.

## 4. Actionability contract

Verdict: PASS.

The existing `Actionability` values are reused: `actionable`, `conditional`,
and `informational`. No numeric score or second priority system was added.
When persisted source lineage is incomplete, non-authoritative, missing, or
matched by a relevant limitation, snapshot explain exposes the bounded
`source_limited` overlay and retains the limitation text.

Legacy direct-script enum spellings are normalized at the explain boundary;
new direct-script snapshots serialize canonical values.

## 5. CLI behavior

Implemented commands:

```text
lde explain <FINDING-ID>
lde explain <FINDING-ID> --json
lde explain <FINDING-ID> --snapshot <schema-3-snapshot>
lde explain <FINDING-ID> --snapshot <schema-3-snapshot> --json
```

Static explain is state-independent and does not run the diagnostic engine.
Snapshot input is schema and compatibility validated. A requested Finding
absent from the snapshot returns a non-fatal, explicit
`NOT_PRESENT_IN_SNAPSHOT` result with no fabricated Evidence.
Unknown or empty IDs return a controlled CLI error without a traceback.

## 13. Known limitations/deferred

- Static explain cannot know runtime severity or confidence, so it exposes the
  explicit `RULE_DERIVED` marker until a validated snapshot is supplied.
- This slice intentionally implements static and snapshot explain, not a new
  live `--current` collection mode. Operators can use the existing `run` or
  `snapshot create` workflow first.
- Several safe guidance commands depend on optional system utilities or source
  permissions. Their unavailability remains a source limitation/unknown state;
  it is not treated as health or resolution.
- Existing report and recommendation prose, including historical remediation
  strings, was not repurposed as public explain investigation guidance.
- No release, tag, publication, or external repair action was performed.

No blocker was found for this bounded integration task.
